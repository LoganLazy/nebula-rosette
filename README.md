# Nebula Rosette · 月历

[项目仓库](https://github.com/LoganLazy/nebula-rosette) · [问题反馈](https://github.com/LoganLazy/nebula-rosette/issues)

> 本地优先的生理期月历：离线记录、周期洞察、PWA、自托管账号同步与可选 AI 助手。

女性生理期日历。记录、预测、周期洞察，支持账号登录与多设备同步、深色模式、可安装为 PWA。

数据默认只存在浏览器里（local-first）：先写本机，登录后才异步同步到自己的服务器。
不登录也能完整使用，连一个网络请求都不会发出去。

**这不是医疗设备。** 预测基于历史周期的统计推算，不用于避孕、受孕或任何医疗判断。
身体状况有疑问请去看医生。

## 跑起来

### 纯前端（不需要账号）

打开 `dist/nebula-rosette.html`。单文件，双击就能用，不需要服务器、不需要联网。
数据存在浏览器里。这个模式下没有账号、没有 AI、装不了 PWA——`file://` 下浏览器会拦一切。

### 带账号和 AI（完整功能）

```sh
cd server
pip install -r requirements.txt
cp .env.example .env          # 填入 LLM_API_KEY
uvicorn main:app --port 8000
```

打开 `http://localhost:8000` —— 后端把前端挂在同源根路径下，不用起第二个服务，
也没有跨域问题。首次进「设置 → 账号与同步」注册一个账号即可。
手机浏览器里用「添加到主屏幕」可以装成 PWA（离线也能打开）。

改完前端源文件后重新打包单文件：

```sh
node build/build.js           # 产物写入 dist/nebula-rosette.html
```

### 部署到服务器（多设备同步）

两种方式选一个，细节见 `deploy/README.md`。

裸机 + systemd（单人自用推荐，改代码即时生效）：

```sh
sudo cp deploy/nebula-rosette.service /etc/systemd/system/
# 改里面的 User / WorkingDirectory / ExecStart 路径
sudo systemctl enable --now nebula-rosette
```

Docker：

```sh
cp server/.env.example .env   # 改 ALLOWED_ORIGINS 为你的域名
docker compose up -d
```

两种方式都只监听 `127.0.0.1:8000`，**不直接暴露公网**。外网访问必须过一层带 TLS 的反代：

```sh
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/rosette
# 改掉里面的域名，然后
sudo certbot --nginx -d rosette.example.com
```

不挂 TLS 的话密码和会话 token 是明文传输，同一网络里任何人都能截获。

注册完自己的账号后把 `.env` 里的 `ALLOW_REGISTRATION` 改成 `0` 再 `up -d` 一次，
否则知道地址的人都能注册。备份用 `sh deploy/backup.sh`——它会同时打包数据库和
`.enc_key`，**只备份 `.db` 等于备份了一堆解不开的密文**。细节见 `deploy/README.md`。

## 数据存在哪

**没登录时** 存浏览器 IndexedDB（不可用时降级 localStorage），不上传任何地方。

**登录后** 同时写本地和服务端 SQLite。顺序是「先写本地，再后台推服务端」——
网络失败不影响记录本身，只在设置页提示同步失败。改动会合并 1.2 秒内的多次操作再推送，
避免连点产生一串请求。

**同步是逐条合并，不是整表替换。** 整表替换会让两台设备互相抹掉对方的改动：
手机改了 3 号、电脑改了 5 号，后推送的那台会把另一天也一起覆盖。现在的规则：

- 比较上次同步快照、本机修改和云端现状；不同记录的改动自动合并，不依赖设备时钟。
- 同一条记录两端都改了且内容不同，保留本机数据并提示冲突，不静默覆盖。
- 经期结束日可以改早或清空。已删除记录不会被另一设备未修改的旧副本恢复。

服务端保留删除版本，前端保存同步基线。同步冲突时可先导出核对，或选择“备份本机并读取云端版本”。
浏览器按服务器地址和账号隔离记录；匿名记录可在退出后通过“查看未登录时的本机记录”访问。
首次登录不会自动上传匿名记录，需要时先导出，再登录并主动导入。
升级与旧设备兼容说明见 [数据可靠性修复](docs-sync-upgrade.md)。

「清空所有数据」和「导入备份」这两个操作语义上就是「让服务端跟本地一致」，
走的是另一个端点 `PUT /api/data/replace`（整表替换），并记录删除版本，防止旧设备恢复已清空内容。

数据库表包括 `users`、`sessions`、`periods`、`notes`、`ai_configs`、`sync_versions`、`sync_deletions`。从属表开了 `ON DELETE CASCADE`，
删账号会连带清掉其所有数据（有测试验证）。

## 账号与安全

口令用 PBKDF2-HMAC-SHA256 加随机盐（26 万次迭代），数据库里存不到明文。
迭代次数以后上调时，用户下次登录会自动升级旧哈希。

会话用随机 token，**数据库只存 token 的 SHA-256**，不存原文——库被读走也无法直接冒用登录态。

登录失败的措辞对「用户不存在」和「密码错误」完全一致，且用户不存在时也会走一次哈希计算，
避免用响应时间探测账号是否存在。登录/注册按来源 IP 限流（默认每分钟 5 次）。
建好自己的账号后可以设 `ALLOW_REGISTRATION=0` 关掉注册。

未登录时所有 `/api/data` 和 `/api/chat` 请求一律 401，账号之间数据严格按 `user_id` 隔离。

改密码在设置页「账号 → 修改密码」。默认会**登出其他所有设备**（当前这台保留），
因为改密码的常见动机就是「怀疑别人知道了」，不清会话等于没改。
新密码走注册时同一套校验规则，不会出现「注册要 8 位、改密码能设 1 位」。
改密码接口按 IP 限流，拿到 token 也不能无限次猜旧密码。

**恢复码**是忘记密码时唯一的进门方式。服务端只存口令哈希，无法还原，所以设置页可以
用当前密码换一批 10 个一次性码（服务端同样只存哈希，明文只在生成那一次的响应里出现）。
用掉一个之后其余全部作废并强制重新生成——一批码只对应一次「我丢了密码」事件。
用恢复码重设密码会作废所有旧会话。没生成过恢复码就还是老结论：忘了密码本地数据仍在，
登录不做强制。

**已登录设备**在设置页列出（设备描述、最后活跃、是否当前这台），可以逐台远程登出。
列表里给的是 token 哈希的短 id，不是 token 本身。

**注销账号**在设置页「账号 → 注销账号」，折叠起来放在红色区块里。它和「清空所有数据」
的区别是后者只清记录、账号还在，注销则把 `users` 行本身删掉——记录、密码哈希、恢复码、
会话、AI 配置全部随 `ON DELETE CASCADE` 消失，用户名重新可被注册。
要密码 + 手打一遍用户名 + 一个 confirm 三道确认：这个按钮紧挨着「清空数据」，
而两者的后果差别是「能重新登录」和「账号没了」，误触代价不对称。
本机记录**不动**——用户注销的是云端账号，不是想丢掉自己的历史。
接口按 IP 限流，拿到 token 也不能靠暴力猜密码删别人的账号。

**反代下的真实 IP。** 所有按 IP 的限流都依赖 `_client_ip()`。直连时
`request.client.host` 就是对的，但一挂到 nginx 后面它会变成 `127.0.0.1`——
所有人共用同一个限流桶，既拦不住撞库，又会让正常用户互相锁死。

所以要读 `X-Forwarded-For`，但这个头客户端可以随便伪造，**默认不信**，
必须显式 `TRUST_PROXY=1` 才启用（`docker-compose.yml` 里已设好，因为容器前面
必然有反代）。取的是最右边那个值：链条形如 `伪造的, 伪造的, 真实客户端`，
只有最右一个是紧邻的反代亲手写上去的。反过来，如果把 8000 直接暴露公网，
必须保持 `TRUST_PROXY=0`，否则等于关掉了登录限流。有三条测试守着这个行为。

## AI 接入：两种方式

设置页可以选：

**走服务端（推荐）** — 浏览器只跟自己的服务器说话，key 不进浏览器。需要先登录，
额度按账号限流（默认每分钟 10 次、每天 200 次），一个账号被限流不影响其他账号。

服务端模式下 key 有两个来源，账号优先：

1. **账号自存**（设置页填）— 每个账号可以存自己的 Base URL、模型名和 API Key，
   保存进 SQLite 的 `ai_configs` 表。
2. **服务端环境变量** `LLM_API_KEY` — 账号没存 key 时的兜底，适合单人自用。

账号自存的 key 用 Fernet（AES-128-CBC + HMAC）加密后才落库，明文不进数据库文件——
有一条测试直接读 `.db` 的字节流断言搜不到明文。加密密钥在 `server/.enc_key`（权限 0600，
首次启动自动生成，已进 `.gitignore`），也可以用 `CONFIG_ENC_KEY` 环境变量指定。

接口永远只回遮掩形式（`sk-…9182`），完整 key 一次都不回传给浏览器，所以设置页看不到
自己存过的 key，只能覆盖或删除。想只改模型名就把 Key 框留空，后端会保留原 key。

这层加密防的是「数据库文件单独泄露」——误提交、备份外泄、只挂了数据卷这类场景。
它不防已经拿到服务器完整权限的攻击者，因为那种情况下密钥文件同样能读到。
**备份数据库时要连 `.enc_key` 一起备份**，只有 `.db` 是解不开的。

**直连** — 在设置页填 Base URL、模型名、API Key，浏览器直接请求模型服务，不需要跑后端。
prompt 约束和安全过滤在前端做了一份等价实现，测试断言两边禁止项一致。

直连的代价：key 存在这台设备的浏览器里。自己用没问题，但别把配好 key 的页面发给别人，
也别部署到公网——任何能打开页面的人都能从 DevTools 里读出 key。
key 不会写进导出的 JSON 备份（有测试守着）。

直连支持任何 OpenAI 兼容端点，填 `.../v1` 即可，代码会自己拼 `/chat/completions`。
本地 Ollama 也能用：Base URL 填 `http://localhost:11434/v1`，key 随便填。
设置页有「测试连接」按钮，会区分 401（key 无效）、模型名错误（大小写敏感）和网络不可达。

不管哪种模式，发出去的只有一段周期摘要：阶段、周期第几天、中位数长度、稳定性、
距下次天数、记录条数，六个数字。具体日期和备注正文不会离开设备，
前后端测试各有一条断言守着（会检查请求体里不出现 `\d{4}-\d{2}-\d{2}`）。

注意：用 `file://` 打开单文件时，浏览器会拦所有跨域请求，账号和 AI 都用不了，
只有纯本地记录可用。要用完整功能就走 `http://localhost:8000`。

## 界面

日历用连续缎带表示经期：一段经期的中间格子是方角，两端才是圆角，视觉上连成一条，
而不是几个孤立的圆点。进行中的经期末端有一层呼吸柔光。预测窗口是淡粉底加虚线上下边框，
预测那天多一圈内描边。排卵期前后用淡紫底，只作阶段层次，不参与任何生育判断。

今天用底部一小段指示条标记，不抢经期的粉色。有记录的日子右上角有小圆点，
颜色跟着流量走（少/中/多三档），痛感 ≥3 会多一个橙点。

状态卡左侧是环形周期进度，中间显示「第几天 / 总天数」。顶栏徽标会显示当前是
「仅存本机」还是「已登录」。

日历卡片有一张玫瑰星云背景图（`assets/backdrop.svg`，纯矢量无外部依赖）。
透明度压到 34% 并叠了一层白纱，因为日历首要任务是读日期，背景抢注意力就是负分。
背景层是伪元素且设了 `pointer-events: none`，不会挡住日期点击。
设置页「外观」里可以关掉。打包单文件时 SVG 会转成 data URI，`file://` 下也能显示。

**预测的经期也画成缎带**，而不是只标一天。窗口表示「可能哪天来」，缎带表示
「来了大概持续到几号」，是两层信息。持续天数取历史已结束经期天数的中位数
（剔除 1 天和 12 天以上的记录——那通常是忘了标结束），没有样本时用 5 天并标注是估算。
缎带可以超出预测窗口，那是正常的。

**提醒横幅**在日历页顶部，不做系统推送。iOS 上 Web Push 要求先手动「添加到主屏幕」
且随时可能不送达，承诺了做不到更糟；打开应用就能看到反而更确定。
横幅只在有话可说时出现：距下次 7 天内、今天预计来、经期进行中、推迟超出窗口、
或一次经期记录超过 12 天（多半是忘了标结束）。落在预测窗口内的「迟」会明说这是正常的，
不制造焦虑。当天手动关掉后不再弹。

**趋势区块**在历史页，把早就存在 `notes` 里但没展示的流量和痛感画出来：
每次经期一条，长度是该次最高痛感，色块是最大流量，并给出「通常第几天最难受」。
只统计落在经期内的记录——非经期的零星备注不代表这次经期的情况。

**经前到经期的逐日热力图**补的是上面那块看不到的东西：按次聚合只回答「有哪些症状」，
看不出时间分布。热力图以经期开始日为原点（那一列有左边框），左边经前 7 天，
右边经期 10 天，每行一个症状，格子深浅是「这一天在多少次周期里出现过」的比例
（用比例而非次数，否则靠后的列样本天然少、看着像症状在减轻）。下面一句话结论给出
「情绪起伏通常提前 3 天开始」和「第 2 天平均最疼」。

窗口取 7 天而不是整个黄体期：再往前会盖到排卵前后，那时的症状和「经前反应」是两回事。
经前窗口里落在上一次经期内的日子会被剔除，否则上次的腹痛会被算成 PMS。
分母的处理是：整次周期一条结构化记录都没有就不进分母（用户当时根本没在记）；
进了分母之后，没记录的日子按「没有该症状」算。偶尔漏记会让比例偏低，
这个方向的偏差是安全的——宁可少报一个模式，也不要凭空造一个。没有样本的列画成斜纹，
和「有样本但没症状」区分开，否则图会撒谎。这段经前模式也会进「给医生的报告」，
门诊问的正是「什么时候开始不舒服」。

**改起止日**在日期弹层里。点开经期内的任意一天，「改这次的起止日」会展开两个日期框，
回填的是**这一段**的起止日而不是你点的那天。之前标错只能删掉整段重记，而删除会进同步
删除队列，等于在所有设备上先抹掉再重建。

校验都在 `P.applyPeriodEdit`（纯函数，可单测）里：结束日不能早于开始日、不能是未来的
日期、跨度不超过 `MAX_BLEED`（12 天，和统计口径共用同一个常量）、不能和别的记录重叠。
重叠判断里，未标结束的那段按 `DEFAULT_BLEED` 估一个范围，否则一段进行中的记录会被当成
只占一天、新段能直接盖上去。结束日留空表示「还没结束」。

同步根据基线识别起始日变化，将旧记录删除并加入新记录；只改结束日则更新原记录，
支持向前纠正和撤销结束。已记的流量、痛感、症状按日期存，改日期不影响它们。

**备份格式 v2。** v1 是在只有「流量 / 痛感 / 文字备注」时定的，后来加了 `symptoms`
但版本号没动——文件里确实有症状，可从版本号上分不出手里这份到底有没有。v2 明确约定
`notes[date]` 是 `{flow, pain, symptoms, text}` 且 `symptoms` 一定是数组。

导入对 v1 和 v2 都只走同一个 `normalizeNote`，不需要一条条迁移脚本（两个版本的周期部分
完全一样）。读取刻意宽容：`pain: "3"` 这种字符串会被接受，`end` 早于 `start` 的脏数据
当成「没标结束」——备份文件是用户手里唯一的数据副本，为一个类型不对就拒绝整份导入，
代价远大于收益。但也不无脑照搬：非法的流量值、越界的痛感、不认识的症状 key、非日期的
键会被丢掉，否则脏值会一路流进统计和图表。比当前版本更新的备份**直接拒绝**并说明
版本号，因为那意味着里面有读不懂的字段，导进来只会静默丢数据。

JSON 是给机器的、能完整导回，
CSV 是给人的、不能导入。一张逐日表（日期、星期、阶段、经期第几天、周期第几天、
流量、痛感、症状、备注），直接丢进 Excel 就能筛选或做数据透视。行的范围是
「有记录的日子」∪「经期内的日子」——后者哪天什么都没记，对医生同样是信息。
两个容易漏的细节：单元格按 RFC 4180 转义（备注里一个逗号就能让整张表错位一列），
以 `=` `+` `-` `@` 开头的文本前补一个单引号防公式注入（这份文件的用途正是发给别人打开），
文件头带 UTF-8 BOM，否则中文表头在简中版 Excel 里是乱码。

**深色模式**在设置页「外观」，三档：跟随系统 / 浅色 / 深色。实现上不给一百多个 class
逐个加 `dark:` 变体（太脆），而是把 Tailwind 颜色全部指向 CSS 变量，
切换只需在 `body` 上加一个 `dark` 类换一组变量。深色下粉色做了降饱和提亮处理，
纯度高的品红在暗背景上会发光刺眼。存的是用户**意图**（`auto`/`light`/`dark`）
而不是当前生效的颜色，否则「跟随系统」会永久失效；选了跟随系统时，
系统切换会实时生效，同时更新 `theme-color` 让手机地址栏跟着变。

**可安装（PWA）**：有 `manifest.webmanifest` 和图标（含 maskable，否则安卓会套白底方框），
Service Worker 只做一件事——离线能打开。它刻意不缓存任何 `/api` 响应（经期数据和 AI 回答
落到磁盘缓存既有隐私问题，也让同步逻辑难以推理），也不注册 push 事件。
`sw.js` 必须从根路径提供并带 `Service-Worker-Allowed: /`，否则作用域管不到首页。
单文件产物里 manifest 引用会被移除——`file://` 装不了 PWA，留着只是一个 404。

## 算法上的几个决定

**周期长度用中位数，不用均值。** 一个 58 天的异常周期能把均值拖高 6 天，
预测就偏出去快两周。中位数不受影响。

**先过滤离群周期。** 不足 21 天或超过 45 天的间隔通常是漏记，不是真实周期，
计算前剔除。

**但离群周期本身计入不规律判断。** 否则一个真正紊乱的用户，
异常周期被过滤掉后剩下几个恰好一致的样本，会被判成「非常规律」——
这是最需要提醒就医的人反而收到了最乐观的结论。现在的规则是：
有离群周期至少降到「有些波动」，离群占三分之一以上直接判「很不规律」。

**预测置信度和稳定性判断共用同一份 CV 阈值表。** 两套阈值会让同一份数据同时显示
「置信度低」和「周期比较规律」。阈值表在 `period.js` 的 `CV_BANDS`，改一处即可。

**日期一律用本地 `YYYY-MM-DD` 字符串。** 用 UTC datetime 的话，东八区用户晚上 8 点
标记会记到前一天。

**经期持续天数也用中位数。** 剔除 1 天以下和 12 天以上的记录——那通常是忘了标结束，
不是真实的经期长度。用来画预测缎带的长度。

## 测试

```sh
node test/period.test.js            # 128 项 算法（含持续天数、提醒、趋势聚合、经前逐日模式、CSV、改起止日校验）
node test/ui.test.js                # 207 项 界面运行时（含导入确认、日期校验、账号隔离与同步冲突）
node test/dist.test.js              # 23 项 单文件产物
cd server && python3 test_main.py   # 143 项 账号、注销、逐条合并、改密码、恢复码、反代真实 IP、AI 代理、Key 加密、PWA 静态资源
python3 -m unittest test_sync -v    # 11 项 同步、日期校验与删除版本回归（在 server 目录运行）
```

共 512 项。CI 在 push 和 PR 上跑同一套（`.github/workflows/tests.yml`），
另外会校验 `dist/` 是否与源文件一致、systemd unit 有没有拼错的键名、
以及 `.env` / `.enc_key` / `*.db` 确实被 `.gitignore` 挡住。

UI 测试用的是 Node 里的最小 DOM stub（本机装不上 Playwright 和 jsdom），
覆盖初始化、事件回调、持久化、降级路径、合并同步、删除队列、主题切换和隐私边界，
但**不覆盖真实布局与视觉效果**——那部分需要在浏览器里自己看一眼，手机上也要试。
深色模式的配色是否舒服、缎带和横幅的观感，只能人眼判断。

## AI 的边界

system prompt 里明确禁止：诊断疾病、推荐具体药物、提供避孕或受孕时机建议（含安全期推算）、
讨论流产性病等敏感话题。服务端模式在后端、直连模式在前端各有一层关键词兜底过滤，
模型越界时替换成引导就医的回复。两份禁止项由测试断言保持一致。

避孕和受孕建议是用户一定会问、但最不该由这类应用回答的问题，所以单独列为禁止项。

## 已知限制

- 同步的删除依赖客户端的删除队列。如果某台设备删了记录后一直没联网、期间被清了浏览器数据，
  那次删除就丢了，下次同步会从服务端拉回来。
- 备注冲突按客户端时间戳判新旧，靠的是设备时钟。设备时间明显不对时可能判错。
- 应用本身不做 TLS。`deploy/nginx.conf.example` 给了反代示例，证书由 certbot 管；
  但**是否真的挂上去要你自己确认**，直接暴露 8000 到公网就是明文传输。
- 备份不自动。`deploy/backup.sh` 要你自己挂到 cron 上，脚本里有现成的一行。
- systemd unit 里的 `ExecStart` 路径和 `ReadWritePaths` 需要按实际安装位置改，
  照抄会起不来（前者报 not executable，后者会让建库失败）。
- 单 worker + SQLite。够一两个人用，但不适合多人并发写入；真要扩容得先换 Postgres。
- 没有系统推送提醒，只有打开应用时的横幅（刻意的选择，见上文）。
- 没有月度分析报告、报告生成图片、伴侣共享。
- 直连模式的 key 存在浏览器里，仅适合自用，不能分发。
- 排卵期推算基于「黄体期长度相对恒定」的假设，只用于视觉分层和小贴士文案，
  不作任何生育相关判断。
